# Reconstruction audit before changes

Compared main 631da87d (growth.lua, silhouette.lua, anatomy.lua, physiology.lua) and anatomy-dev 7f4230a (body_parts.lua, anatomical_growth.lua, anatomical_rendering.lua, anatomy_dev_ui.lua, development.lua). Local copies match the revisions delivered in the prior pass. Target for this request is desktop-laboratory-dev; main and anatomy-dev remain intact.

The 7f4230a constructor always lays chest/abdomen/pelvis on a horizontal serial axis. Limbs are mostly downward beams; head capsules and snouts follow the same forward arrangement. Multiple heads vary height but repeat their proportions. Counts vary, yet skeletal topology within a region remains one generic support. This explains dog-like convergence despite the numerical configuration count.

Both main and the anatomy branch used one primary support and one generic muscle per region. Neither had a detailed vertebral/rib/phalangeal skeleton to restore literally. Main did preserve richer tissue tile visualization, airway/gill/surface overlays, organ and vascular display, and condition marking. The new renderer omitted several of these and reduced muscle/fat coverage to scaled region profiles, a real inspection regression. The repair must preserve those functions while adding genuinely connected skeletal substructures rather than claiming old detail existed.

The snapshot viewer advances one state per 0.6 seconds and discards excess accumulated time. Buds, all heads, organs and coverings appear between eleven coarse snapshots; its physiology panel always reads the adult body. Incubation constructs the whole anatomy after 35% progress and scales aggregate tissue totals. Juveniles only scale their renderer size: no growing skeletal dimensions or tissue volumes. Physiology stores fatMass separately from canonical fat tissues, so reserve use does not alter external contours or physical mass. These are simulation/state problems, not cosmetic issues.

Repair architecture: retain the canonical genome, region/component arrays, physiological APIs, archives and legacy bodies. Expand actual support/tissue graphs, store persistent target/current anatomy and developmental schedules on those same records, evaluate growth continuously by elapsed biological time, keep renderer interpolation separate, calculate capabilities from the current graph, and blend tissue-derived cross sections into a single surface. Add reproducible skeletal topology and growth measurements, not just silhouette counts.
